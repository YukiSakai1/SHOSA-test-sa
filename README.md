# SHOSA - ホテルスタッフ体験アプリ

外国人ホテルスタッフが日本の職場での「所作（SHOSA）」を、選択肢形式のショートストーリーで学ぶ
アプリです。

## フォルダ構成
```
shosa-game/
├── index.html              HTML構造のみ（画面の骨組み）
├── css/
│   └── style.css           全スタイル定義
├── js/
│   ├── game_data.js        ゲーム本編の内容（Day1〜3のシナリオデータ）
│   ├── onboarding_data.js  0章（登録〜SHOSAパスポート完成）の内容データ
│   ├── app.js               ゲーム本編の画面遷移・スコア計算・音声認識ロジック
│   └── onboarding.js        0章の画面遷移・状態管理ロジック
│   └── dev_overview.js      開発者ビュー（全イベント俯瞰表示）の生成ロジック
└── assets/
    ├── images/
    │   └── avatars/         キャラクター画像6枚（プロフィール用アバター & NPC表示に使用中）
    └── audio/               発音サンプルの音声ファイルを追加する場合はここに配置（任意）
```

## 使い方
`index.html` をブラウザで開くだけで動きます（サーバー不要）。
ただし音声認識（マイク）機能を使う場合は `https://` または `localhost` 環境で開いてください
（ブラウザのセキュリティ制約により `file://` では音声認識がブロックされることがあります）。

## 「戻る」機能について
画面上部に「← 戻る」ボタンが表示され、いつでも1つ前の画面に戻れます（何度でも押せば、
好きなだけ前の画面まで遡れます）。単に画面を戻すだけでなく、以下も「戻った時点」の状態に
正しく復元されます。
- ヒアリングや適性診断で選んだ回答（選択状態がハイライト表示され、NEXTボタンも押せる状態に戻る）
- プロフィール入力欄（名前・生年月日・性別・アバターなど）
- チーム度／ゲスト安心度などのスコアや、Dayごとの評価ゲージ
- 完了日数やハイスコア

戻ってから別の選択肢を選び直した場合も、スコアが二重に加算されることはありません
（`js/app.js` の `goTo()` / `goBack()` が、遷移のたびに `state` と `obState` を丸ごと
スナップショットして管理しているため）。新しく画面を追加する場合も、遷移箇所を
`showScreen('id')` の直接呼び出しではなく `goTo(loaderFn, ...args)` に統一すれば、
自動的にこの「戻る」機能の対象になります。

## キャラクター画像について
`assets/images/avatars/` の6枚は、プレイヤーが「プロフィール入力02」で選ぶアバターとして使われるほか、
Day1〜3に登場する「チーフ（上司）」「先輩スタッフ」のNPC画像としても使用しています
（`js/game_data.js` の `npc.avatar` と `js/onboarding_data.js` の `avatarOptions` を参照）。

絵文字と画像は共通の仕組みで表示しており、`avatar` の値が画像ファイルのパス（.jpg等で終わる文字列）なら
自動的に `<img>` として、それ以外（絵文字文字列）ならテキストとして表示されます
（`js/app.js` の `renderAvatar()` 関数）。画像を差し替えたい場合は、同じファイル名で
`assets/images/avatars/` 内のファイルを上書きするか、データファイル側のパスを書き換えてください。

## 0章（オンボーディング）の流れ
`START` を押すと、ゲーム本編の前に以下の流れが挟まります（Figmaワイヤーフレーム「0章」に対応）。

1. 登録開始（SHOSAタイトル）
2. SHOSA Ready CHECK（日本語レベル確認・言語表示設定）※最初に設定
3. キャラクター紹介（Welcome〜検定/就職サポートまでの4枚カルーセル＋AIチューター挨拶）
4. ヒアリング01〜04（経験・希望職種・興味・不安）
5. 適性診断（5段階評価 × 5問）
6. プロフィール入力01（性別／名前／生年月日）
7. プロフィール入力02（アバター・音声タイプ設定）
8. SHOSAパスポートの完成（適性診断結果をスターで表示）→ ここから本編Day1へ

※ 元の11項目の「ヒアリング03（レベル確認）」は、実際のFigma画面順に合わせて
「SHOSA Ready CHECK」として登録開始の直後（キャラクター紹介より前）に移動しています。
ここで入力した名前は、以降の本編ストーリー中の「○○」という箇所に自動で反映されます。

## キャラクターの「生きている感」演出
本物のまばたき・口パクアニメーションを作るための素材（目を閉じたコマ、口を開けたコマ等）は
今のところ用意していません。代わりに、静止画でも不自然にならない2つの演出を入れています。
- **アイドルモーション**: NPCの大きい画像に、ゆっくりした呼吸のような拡大縮小・上下の揺れを
  CSSアニメーションで付けています（`prefers-reduced-motion` 設定を尊重し、視差に弱い方には
  自動でオフになります）。
- **タイプライター表示**: 会話・結果・発音練習画面のセリフを一文字ずつ表示し、「話している感」を
  演出します。吹き出し／台本カードをタップすると即座に全文表示にスキップできます。英訳
  （English >）を開いた時も、対応する日本語側が自動で全文表示に切り替わります。

もし今後、表情差分のように「目を閉じた」「口を開けた」コマ画像を追加で用意できれば、
`renderAvatar()` / `npcBannerSrc()` と同じ仕組みで、それらをアニメーションのコマとして
切り替える本格的なまばたき・口パクにも拡張できます。

## タイトル画面から「詰まない」ように
全Dayクリア後、何度か「← 戻る」で遡ってからブラウザを閉じたり、「最初からやり直す」を押して
タイトルに戻った場合でも、迷子にならないようにしています。保存済みのプロフィールや
プレイ済みのDayが1つでもあれば、タイトル画面に「🏠 続きから（Day選択メニューへ）」ボタンが
自動で表示され、ワンタップでメニュー（Day選択）画面に直接ジャンプできます。
「← 戻る」を何十回も押して遡る必要はありません。

## メニュー（Day選択）：好きなところへ自由に行き来
以前は全Dayをクリアすると「もう一度プレイ」で最初(タイトル)に戻るだけでしたが、
今は全Day完了後に自動で「メニュー画面」が表示され、そこから：
- 好きなDayを選んですぐにプレイ・やり直しができる（★の評価も表示されます）
- 📔「SHOSAパスポートを見る」で自分のプロフィールをいつでも見返せる
- 「最初からやり直す」で完全にリセットして最初から

さらに、⚙️ 設定画面の「🏠 Day選択メニューを開く」からは、プレイの途中でも
このメニューをいつでも呼び出せます（全Day未完了の場合は「ここまでの進捗」表示になります）。

Dayをやり直しても完了日数（`completed-days`）が二重にカウントされることはなく、
やり直した回の★評価で上書きされる設計です。

## タイトル画面の画像
タイトル画面は、人物の丸アイコンではなく「ホテル未来」ロビーの情景画像
（`assets/images/scenes/title_lobby.jpg`）を横長のバナーとして表示しています。
差し替えたい場合は同じファイル名で上書きするか、`index.html` の `.title-scene-img` の
`src` を変更してください。

## NPCの大きい表示・表情の切り替え
イベント導入・会話・質問・結果・発音練習の5画面で、NPCを小さい丸アイコンではなく
画面幅いっぱいの大きい画像（バナー）で表示しています。結果画面では、選んだ選択肢の
評価に応じて表情も自動で切り替わります。
- BEST（正解） → 笑顔の画像
- OKAY（まあまあ） → ニュートラルな画像
- BAD（イマイチ） → 困り顔の画像

これは `js/game_data.js` の各Dayの `npc` オブジェクトに `bannerNeutral` / `bannerHappy` /
`bannerWorried` の3枚を登録することで有効になります（Day1・Day2・Day3の全NPCで使用中）。
表情違いの画像を用意していないNPCは、自動的に`avatar`（1枚のみ）が全表情で使い回されるので、
エラーにはなりません。

現在のNPC構成：
- Day1・Day3: チーフ（上司） — Day1は田中安一（`staff_male_03`系）、Day3は別スタッフ
  （`staff_male_01`系、いただいた画像で表情差分3枚を追加）を使用しています。
  ※同じ「チーフ（上司）」という名称のまま画像だけ変えている状態なので、日によって別人が
  写るのが意図通りかどうか、必要であれば名称の変更もご相談ください。
- Day2: 先輩スタッフ（`staff_female_03`系）

**サイズの統一**: 全キャラクター・全表情の画像は `372×279`（4:3）に統一しています。
髪の生え際とジャケットの肩ラインを画像解析で検出し、全員の「頭からジャケット上端までの距離」が
揃うように拡大縮小してから統一の範囲でクロップし直した上で、最終的に372×279へリサイズしています。
これにより、どのキャラクター・どの表情・どの画面でも上半身の見える範囲がそろい、
English翻訳を開いて文章が増えた場合でもスクロールなしで収まりやすくなっています。
新しく画像を追加する場合も、同じ考え方（頭部スケールを揃えてから同じ範囲・同じサイズで
切り出す）で作ると統一感を保てます。

## 開発者ジャンプメニュー（⚙️ 設定 → 🧭 画面ジャンプ）
開発を進めやすいように、設定画面の中に「どの画面へも直接ジャンプできるメニュー」を追加しています。
タイトル画面を含め、アプリ内のどこからでも ⚙️ 設定 → 🧭 画面ジャンプ（開発用）を開けば、
SHOSA Ready CHECKから各Day・SHOSAパスポート・メニューまで、全14画面に一直線に飛べます
（`goTo()` 経由なので「戻る」で普通に戻れます）。毎回オンボーディングを最初から
やり直さなくても、特定の画面だけをすぐ確認・テストできます。

## 開発者ビュー（全イベント俯瞰表示）
設定画面（⚙️ 設定）の一番下に「🛠️ 開発者ビュー（全イベント一覧）を開く」ボタンがあります。
押すと、スマホフレームの外にフルスクリーンのオーバーレイが開き、以下がすべて俯瞰できます。
- 0章（オンボーディング）：SHOSA Ready CHECK → キャラクター紹介 → ヒアリング4問（選択肢も全表示）
  → 適性診断5問 → プロフィール入力 → パスポート完成、という流れ全体
- ゲーム本編（DAY1〜3）：各Dayの①イベント導入 → ②会話 → ③質問 → ④3つの分岐（選んだ選択肢の
  フィードバック・スコア変化量・ポイントを色分け表示：緑=BEST/青=OKAY/赤=BAD）→ ⑤解説 →
  ⑥発音練習、まで一直線に表示

これは `js/game_data.js` と `js/onboarding_data.js` の中身をその場で読み取って自動生成しているだけの
読み取り専用ツールなので、シナリオを追記・編集すればこの画面にも自動的に反映されます
（`js/dev_overview.js`）。ゲームの進行状況やスコアには一切影響しません。

## English翻訳トグルについて
質問画面だけでなく、Day1〜3の以下の画面すべてに「English >」トグルを追加しています。
タップすると英訳が表示され、もう一度押すと「日本語 >」に切り替わって日本語表示に戻ります。
- イベント導入画面（ストーリー・ヒントの2箇所を1つのボタンで同時に切り替え）
- 会話画面
- 質問画面（既存）
- 結果画面
- SHOSA解説画面
- 発音練習画面（台本テキストのみ。お手本音声は日本語のまま再生されます）

英訳は `js/game_data.js` の各テキストに対応する `*_en` フィールド（`story_en` / `hint_en` /
`dialogueText_en` / choicesの `feedback_en` / `explanation.body_en` / `voice.script_en`）に
入っています。Day4以降を追加する際は、日本語と一緒に英訳も入れておくと自動的にトグル対象になります。

## シナリオを追加・編集する
- ゲーム本編（Day4以降など）は `js/game_data.js` の `GAME_DATA.days` 配列に追加。
- 0章の質問・カルーセル内容は `js/onboarding_data.js` を編集。
どちらも `app.js` / `onboarding.js` 側の変更は基本的に不要です。

## プロフィールの保存・あとからの変更
プロフィール入力01/02（性別・名前・生年月日・アバター・音声タイプ）は`localStorage`に自動保存され、
次回このアプリを開いた時もオンボーディングのプロフィール画面に自動で反映されます。

また、画面右上の「⚙️ 設定」ボタンから、いつでも（タイトル画面でもゲームプレイ中でも）
プロフィールを開いて編集できます。保存するとヘッダーの表示やストーリー中の名前（○○の部分）が
即座に更新され、そのあと「戻る」でどれだけ前の画面まで遡っても、編集後の内容が保たれます
（`js/app.js` の `patchHistoryObState()` が、保存済みの全履歴に変更を反映しているため）。

また、一度プロフィール・ヒアリング・適性診断のすべてに回答していれば、次回以降は
キャラクター紹介の直後に、ヒアリング → 適性診断 → プロフィール入力01/02の3ステップを
まとめて自動スキップし、そのままSHOSAパスポート画面に進みます
（それぞれ保存内容が揃っている場合のみスキップされ、一部だけ未回答ならその部分だけ表示されます）。
内容を変更したい時は、⚙️ 設定からいつでも編集・再回答できます。

## 機能メモ
- ハイスコアはブラウザの `localStorage` に保存され、再訪問時も残ります。
- 発音練習は対応ブラウザ（Chrome等）では Web Speech API（音声認識）を使用し、
  非対応環境では自動でシミュレーション版にフォールバックします。
- お手本再生には `speechSynthesis`（ブラウザ標準の音声合成）を使用しています。

## BGM（背景音楽）
`assets/audio/` に4曲入っています。すべて約22〜30秒でシームレスにループするアンビエント曲で、
AI音楽生成モデルではなくPythonでのサイン波合成（コード進行＋ペンタトニックのチャイム＋薄い
ノイズ質感、Day1とDay3は軽いプラック音も追加）で作成しています。
- `lobby_bgm.mp3` — タイトル画面・0章（オンボーディング）・DayとDayの間（Day終了サマリー）・
  メニュー（Day選択）で使用。落ち着いたホテルロビー風
- `day1_bgm.mp3` — DAY1（報連相）用。明るく前向き、軽快なプラック付き
- `day2_bgm.mp3` — DAY2（クッション言葉・おもてなし）用。優雅でドリーミー、チャイム多め
- `day3_bgm.mp3` — DAY3（総仕上げ・忙しいディナータイム）用。わずかな緊張感から前向きに、
  テンポ感のあるプラック付き

曲の切り替えは `js/app.js` の `playBgm(track)` が担当し、すでに同じ曲が再生中なら何もしない
（無駄な巻き戻りをしない）ようになっています。どのDayでどの曲を鳴らすかは
`js/game_data.js` の各Dayの `bgm` フィールドで指定しているので、Day4以降を追加する時は
同じように音源ファイルを用意して `bgm: "assets/audio/dayX_bgm.mp3"` を追加するだけです。

画面右上の🔊/🔇ボタンでいつでもミュート切り替えができ、その設定は`localStorage`に保存されて
次回以降も引き継がれます。ブラウザの自動再生制限があるため、タイトル画面の「START」を押した
タイミング（＝最初のユーザー操作）で再生を開始します。

## レイアウトの不具合修正（2026/07）
- **CSSリセットの不備**: 全体の `box-sizing: border-box` 指定がセレクタ抜けで実際には
  一切適用されていなかったバグを修正しました。これが原因で、設定画面の名前・生年月日の
  入力欄が横にはみ出してスクロールしてしまう問題が起きていました。
- **タイトル画面の画像**: 画面幅を超えてはみ出す量を少し小さくし、`main` 要素に
  `overflow-x: hidden` を安全策として追加。横スクロールが起きないようにしました。
- **開発者ビューのヘッダー**: `position: sticky` はネストしたスクロール領域内だとブラウザに
  よって挙動が不安定になることがあるため、ヘッダーをスクロール領域の外に出し、
  「上部固定ヘッダー＋その下だけスクロール」というシンプルなflexレイアウトに変更しました。

また、⚙️ 設定画面には「🗒️ ヒアリングをやり直す」「📊 適性診断をやり直す」ボタンがあり、
いつでも再回答できます（保存済みの回答が選択済み状態で表示されるので、変えたい部分だけ
選び直せます）。再回答すると保存内容も更新されます。
